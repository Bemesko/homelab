# 002 — Secrets with SOPS + age, decrypted by Ansible

- **Status:** accepted; app secrets evolved to KSOPS in [004](004-ksops.md); who holds the key and the recipients changed in [016](016-control-node-raspberry-pi.md) (the control node is a Raspberry Pi, plus a recovery key)
- **Date:** 2026-10-31

## Context

The repository is public. The only secret today is the Tailscale Operator OAuth client, and the cluster lives on a laptop and will be rebuilt every now and then.

## Options

| | SOPS + age | Sealed Secrets |
|---|---|---|
| Where the private key lives | a `keys.txt` file you hold (backed up in the password manager) | inside the cluster (generated by the controller) |
| What gets encrypted | the values of any YAML; keys stay readable in the diff | only Kubernetes `Secret`s (CRD `SealedSecret`) |
| Works for Ansible variables | yes (`community.sops`) | no |
| Rebuilding the cluster | just needs `keys.txt` | needs a backup of the controller key, or sealing everything again |
| ArgoCD integration | needs a plugin (KSOPS/helm-secrets) if ArgoCD decrypts | native (it is just a manifest) |

## Decision

SOPS + age, with decryption done **by Ansible on the controller** during the bootstrap, which creates the `Secret`s in the cluster with `no_log`. The private key never reaches the laptop or the cluster, and ArgoCD needs no plugin.

## Consequences

- A new Secret that ArgoCD has to manage continuously will require moving to KSOPS (with the age key in the cluster). That is left as a future evolution.
- CI uses an ephemeral age key and dummy secrets, which exercises the same decryption path.
